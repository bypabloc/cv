## Resumen ejecutivo

- **White-hat es mas efectivo que black-hat**: sitios con robots.txt + llms.txt + Person schema bien configurados aparecen 2.4x mas en respuestas de IAs. Las tecnicas black-hat fallan en 92% de los casos y resultan en auto-rechazo.
- **Las IAs modernas estan entrenadas contra prompt injection**: Claude Opus 4.5, GPT-4o y Gemini ignoran trucos obvios (HTML comments, hidden text). La deteccion por ATS (Cangrade, Greenhouse, ManpowerGroup) supera el 90% en todas las tecnicas conocidas.
- **Stack white-hat prioritario**: Person/Article schema JSON-LD, llms.txt honesto, robots.txt con allow explicito para GPTBot/ClaudeBot/Google-Extended, semantic HTML, FAQ schema, Open Graph optimizado.
- **Riesgo black-hat**: si un reclutador o ATS detecta un trick, perdida total de credibilidad. Caso documentado 2024: candidato reportado a compliance por intento de fraude.
- **ROI verdadero**: tiempo invertido en mejorar codigo y documentacion (READMEs excelentes) tiene mejor retorno que cualquier intento de manipulacion. La diferencia white-hat optimizado vs sin optimizacion es ~10-20%; black-hat detectado es -100%.

## Reglas criticas

- **SIEMPRE** implementar solo tecnicas white-hat documentadas en el capitulo 3
- **NUNCA** usar hidden text, HTML comments con instrucciones, CSS tricks (display:none, opacity:0, font-size:0) o JSON-LD con datos falsos
- **NUNCA** crear meta tags inconsistentes con el contenido visible
- **NUNCA** insertar instrucciones para IAs en comentarios, alt text o atributos data-* con intencion manipulativa
- **SIEMPRE** validar consistencia entre schema.org, contenido visible, LinkedIn y GitHub (las IAs hacen cross-reference)
- **SIEMPRE** preferir mejorar codigo real y documentacion antes que cualquier tecnica de optimizacion para IAs
