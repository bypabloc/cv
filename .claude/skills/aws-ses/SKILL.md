## Reglas criticas (siempre activas)

1. **SIEMPRE** SES v2 API (`sesv2` boto3 client), NUNCA v1 (`ses`
   client deprecado). V2 tiene mejor deliverability + nuevos features.

2. **SIEMPRE** verificar el dominio (no solo el email individual). Domain
   identity = cualquier `<algo>@<domain-verified>` puede enviar. Easy
   DKIM en SES emite 3 CNAMEs autogenerados, agregar en Cloudflare DNS
   con proxy OFF (DNS only). Con proxy ON, DKIM verification falla.

3. **SIEMPRE** configurar SPF + DMARC ademas de DKIM. Sin los 3, Gmail/
   Outlook marcan como spam:
   - SPF: `TXT v=spf1 include:amazonses.com -all` (o `~all` durante setup)
   - DMARC: `TXT v=DMARC1; p=quarantine; rua=mailto:dmarc@<domain>` (testing) → `p=reject` (prod)

4. **SIEMPRE** Production access antes de prod-launch. Sandbox solo
   permite envio a addresses verificadas + 200 emails/24h. Solicitud
   via AWS Console "SES > Account dashboard > Request production
   access" con descripcion del use case (transactional, low volume,
   verified domain). Approval: 24-48h.

5. **SIEMPRE** multipart email: HTML + plain text fallback. Sin plain
   text, Gmail/Outlook deliverability sufre. boto3 ejemplo:
   ```python
   ses.send_email(
       FromEmailAddress='no-reply@verified-domain.com',
       Destination={'ToAddresses': ['owner@example.com']},
       Content={
           'Simple': {
               'Subject': {'Data': '...', 'Charset': 'UTF-8'},
               'Body': {
                   'Text': {'Data': '...', 'Charset': 'UTF-8'},
                   'Html': {'Data': '...', 'Charset': 'UTF-8'},
               },
           },
       },
   )
   ```

6. **NUNCA** envio email con CSS Grid/Flexbox layout. Outlook 2007-2019
   no soporta. Usar tables-based layout o MJML framework. Max width
   600px, fonts web-safe (Arial, Verdana, Georgia, Helvetica, Times).

7. **NUNCA** IAM policy con `ses:*`. Scope: `ses:SendEmail` +
   `ses:SendRawEmail` con condition:
   ```yaml
   - Effect: Allow
     Action: [ses:SendEmail, ses:SendRawEmail]
     Resource: arn:aws:ses:us-west-2:*:identity/the-full-stack.com
     Condition:
       StringEquals:
         ses:FromAddress: 'no-reply@the-full-stack.com'
   ```

8. **SIEMPRE** Account-level Suppression habilitado. SES auto-mantiene
   lista de emails que bouncearon o se quejaron. NO les vuelve a enviar
   = protege reputation. Sin suppression, AWS te suspende si bounce > 5%.

9. **SIEMPRE** verificar la skill antes de modificarla con
   `claude --permission-mode bypassPermissions -p` (regla
   [.claude/rules/claude-config-testing.md](../../rules/claude-config-testing.md)).

## Atajos rapidos

### "Como envio un correo desde Lambda?"

Codigo basico en [04-send-email-python.md](../../docs/aws-ses/04-send-email-python.md):

```python
import boto3
from botocore.exceptions import ClientError

ses = boto3.client('sesv2', region_name='us-west-2')

def send_contact_notification(payload: dict) -> str:
    try:
        response = ses.send_email(
            FromEmailAddress='no-reply@the-full-stack.com',
            Destination={'ToAddresses': ['pacg1991@gmail.com']},
            Content={
                'Simple': {
                    'Subject': {'Data': f"Nuevo contacto: {payload['name']}", 'Charset': 'UTF-8'},
                    'Body': {
                        'Text': {'Data': render_plain(payload), 'Charset': 'UTF-8'},
                        'Html': {'Data': render_html(payload), 'Charset': 'UTF-8'},
                    },
                },
            },
        )
        return response['MessageId']
    except ClientError as e:
        # Log + retry o fail
        raise
```

### "Como configuro DKIM/SPF/DMARC en Cloudflare?"

Pasos en [03-domain-verification-dns.md](../../docs/aws-ses/03-domain-verification-dns.md):

1. AWS Console > SES > Verified identities > Create > Domain
2. Toggle "Easy DKIM" (default) > AWS muestra 3 CNAMEs
3. Cloudflare Dashboard > DNS > Add records:
   - 3x CNAME (DKIM, proxy OFF / DNS only)
   - 1x TXT SPF: `v=spf1 include:amazonses.com -all`
   - 1x TXT DMARC en `_dmarc.<domain>`: `v=DMARC1; p=quarantine; rua=mailto:dmarc@<domain>`
4. Esperar verificacion (DKIM tarda hasta 24h, SPF/DMARC instant)

### "Cuanto va a costar?"

200 emails/mes = **$0.02/mes** ($0.10 per 1000) o **$0/mes** si free
tier desde Lambda aplica (62000 emails/mes free). Detalle y comparacion
con SendGrid/Resend/Postmark en
[09-cost-comparison-2026.md](../../docs/aws-ses/09-cost-comparison-2026.md).

## Anti-patrones a evitar

- Responder con SES v1 API (deprecated)
- Olvidar plain text fallback (HTML only = spam)
- Configurar DKIM con proxy ON en Cloudflare (DNS only required)
- Email HTML con CSS Grid/Flexbox (Outlook no renderea)
- Hardcodear from address en codigo (usar env var + SAM `!Ref`)
- IAM policy con `ses:*` "for simplicity"
- Mandar a prod sin DMARC `p=quarantine` minimo
- Ignorar bounce/complaint emails (lleva a suspension AWS)
- Recomendar SendGrid free para portfolio con AWS infra
- Saltarse production access "porque sandbox es suficiente"

## Comandos utiles

```bash
# Verificar identidades verificadas
aws sesv2 list-email-identities --region us-west-2

# Detalle de un identity (DKIM status)
aws sesv2 get-email-identity \
  --email-identity the-full-stack.com \
  --region us-west-2

# Send quota actual
aws sesv2 get-account --region us-west-2 \
  --query 'SendQuota'

# Verificar DNS records correctos
dig +short CNAME <dkim-token>._domainkey.the-full-stack.com
dig +short TXT the-full-stack.com | grep spf
dig +short TXT _dmarc.the-full-stack.com

# Send test email
aws sesv2 send-email \
  --from-email-address no-reply@the-full-stack.com \
  --destination 'ToAddresses=test@example.com' \
  --content '{"Simple":{"Subject":{"Data":"Test"},"Body":{"Text":{"Data":"Test"}}}}' \
  --region us-west-2
```
